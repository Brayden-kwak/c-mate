4. 개선안

STRUCTURE — 구조 개선

S-1. 질문 성격별 섹션 그룹화 P0

문제 정의  ·  20개 섹션이 평면 리스트로 나열되어 사용자가 "어디쯤 작성 중인지" 가늠하기 어렵다.

검증 결과  ·  결혼경험·주소·교회·학력·신체·생활습관·사진이 모두 동일한 비중·간격으로 나열되고, 모바일에서는 스크롤 깊이가 매우 길어져 인지부하가 가중된다.

S-2. 5단계 상단 프로그레스바에 단계명 라벨 P0

문제 정의  ·  페이지 상단의 5단계 progress bar에 단계 번호만 있고 명칭 라벨이 없어 사용자가 다음 단계가 무엇인지 예측할 수 없다.

  • 본문 위에는 1. 기본정보(현재) / 2. 나의소개 / 3. 매력어필 / 4. 라이프스타일 / 5. 이상형정보 형태의 리스트만 존재

  • 모바일에서는 리스트가 없어 단계명 인지가 더더욱 어려움

R-2. 모바일 퀵 버튼(+/TOP) 인터랙션 오류 P0

문제 정의  ·  모바일에서 우측 하단 "+" 퀵버튼을 누르면 같은 자리에 "맨위로" 버튼이 나타나고, 닫기(X)는 보이지 않으며, 의도치 않게 한 번 더 누르면 페이지가 맨 위로 튄다.

검증 결과

  • 화면 우측 하단에 ＋ 버튼 + 위쪽 ↑(맨위로) 버튼이 같이 노출되어 트리거 위치가 충돌
  • "＋" 클릭 후 상태에서 닫는 명시적 컨트롤이 없음

개선안

  • ＋" 클릭 → 같은 자리에 X(닫기)로 변환. aria-expanded 동기화
  • 메뉴 열림 시 위쪽으로 5개 메뉴 항목(자녀결혼·업그레이드·오시는길·프로필컨설팅·33법칙)이 stack으로 펼침
  • 모바일에서 "맨위로" 버튼은 제거 (작은 화면에서는 손가락 스크롤이 더 자연스러움)
  • 화면 회전 시 FAB은 닫힘 상태로 리셋. ESC 키로도 닫힘
  • 접근성 — aria-expanded, aria-controls, aria-label 상태 토글

R-3. 모바일→데스크탑 리사이즈 시 햄버거 메뉴 닫힘 버그 P0

문제 정의  ·  모바일에서 햄버거 메뉴를 연 상태에서 브라우저 폭을 데스크탑 사이즈로 늘리면, 메뉴가 닫히지 않은 채로 표시가 깨지고 퀵 버튼·맨위로 버튼이 사라진다.

개선안

  • 윈도우 리사이즈 이벤트에서 모바일 → 데스크탑 전환 시 햄버거 메뉴 상태를 강제 닫힘으로 전환
  • 햄버거 메뉴 자체가 데스크탑 브레이크포인트 이상에서는 렌더되지 않도록 컴포넌트 자체를 unmount
  • 1023px 이하에서는 desktop view라도 mobile-like app shell(앱 헤더, 햄버거, 드로어, chip stepper, FAB)로 전환

QA 검증 시나리오

  1. 모바일에서 햄버거 오픈 → DevTools로 1440px로 변경 → 햄버거 자동 닫힘
  2. 변경 후 퀵 버튼 / 사이드바 정상 노출
  3. 다시 모바일 폭으로 줄여도 햄버거가 자동 오픈되지 않음

🔁 INTERACTION — 인터랙션 개선

I-1. 주소 — 상세 주소 입력 텍스트박스 추가 P1

문제 정의  ·  현재 주소 필드는 도로명/지번이 검색을 통해 채워지지만, 사용자가 직접 입력해야 하는 상세 주소(동·호수·건물명 등)를 받는 별도 input이 없다.

개선안 — Highlight Box 패턴

  • 주소 검색 결과 표시 박스 하단에 "상세 주소" 박스 영역 신규 추가
  • 박스 헤더에 "상세 주소" + "선택" 태그 표시 (필수 아님을 명확화)
  • placeholder: "동/호수, 건물명 등 (선택 입력)"
  • 50자 제한 (counter UI 노출)
  • helper text: "매니저 검수용으로만 사용되며, 다른 회원에게는 지역까지만 노출됩니다."

엣지 케이스

  • 해외 주소 선택 시 검색 대신 자유 입력 1줄, 상세주소 input은 그대로 유지
  • 사용자가 검색 후 상세 주소를 입력하지 않아도 저장 가능 (선택)

I-6. 포토북 "+" 버튼 동작 오류 + 위치 변경 P1

문제 정의  ·  포토북에서 "+" 버튼을 누르면 새 슬롯이 추가되는 위치가 잘못되어 이미 등록된 이미지가 뒤로 밀려나는 현상 발생.

검증 결과  ·  현재 등록된 1장 + "+" 버튼이 노출된 상태에서 "+"를 클릭하면 새 빈 슬롯이 기존 이미지 앞에 삽입되어 기존 이미지의 인덱스가 뒤로 밀린다.

개선안

  • "+" 버튼은 항상 마지막 등록된 사진의 뒤에 위치 (trailing add slot 패턴)
  • 새 슬롯도 마지막 사진의 다음 인덱스로 push
  • 사진 위치 변경(drag & drop, 모바일 carousel reorder) 함께 제공 (I-5와 동일 패턴)
  • 8장 모두 등록되면 "+" 버튼은 hidden 또는 disabled + 툴팁 "포토북은 최대 8장까지 등록할 수 있어요"

5.9 Do / Don't

✓Do
  • primary는 화면 핵심 액션 1개에만 사용
  • 필수 미입력은 outline + inline error + toast 병행
  • 삭제/손실 가능 액션은 danger 버튼
  • 자동 저장 상태를 chip으로 항상 표시
  • 아이콘 버튼에 aria-label 필수
  • 웹/모바일 필드 목록을 동일하게 유지
✗Do not
  • 저장하기 + 다음을 둘 다 primary로 표시
  • 스타일을 그룹별 5개로 오해시키기
  • 모바일 FAB을 desktop frame 끝에 dock
  • 모바일 푸터에 21px 초과 타입 사용
  • 토큰 외 리터럴 hex/px 사용
  • 모달 안 모달 중첩
